## 진행 방식

```
세미나 → 과제 수행 → PR 제출 → 다음 주 세미나에서 리뷰
```

세미나 시간은 개념을 처음 배우는 자리가 아니라, **각자 만들어 온 걸 공유하고 막힌 지점을 푸는 자리**입니다. 자료는 노션으로 먼저 공개되니, 세미나 전까지 자료를 읽고 과제를 완료한 뒤 참여해주세요.

| 시점 | 하는 일 |
| --- | --- |
| 세미나 직후 ~ 다음 세미나 전 | 자료를 읽고, WINK PLAY에 그 주 내용을 구현하고, 과제 PR을 올립니다 |
| 세미나 (매주 목요일 18:30) | ① 지난 과제 리뷰 → ② 랜덤 발표 → ③ 이번 주 챌린지 해설 → ④ 다음 주 예고 |

## 기술 스택과 규칙

HTML · CSS · JavaScript, 그리고 제출과 배포를 위한 Git/GitHub · GitHub Pages를 사용합니다.

- **프레임워크 · 라이브러리 금지**: React, Vue, jQuery, Bootstrap, Tailwind 등을 쓰지 않습니다.
- **빌드 도구 · 패키지 설치 금지**: `npm install` 없이 동작해야 합니다.
- **외부 리소스 금지**: CDN, 웹 폰트, 외부 이미지 링크 없이 폴더 안의 파일만으로 동작해야 합니다.
- **더블클릭으로 실행**: `index.html`을 브라우저로 열었을 때 바로 동작해야 합니다. 4주차에는 같은 파일을 GitHub Pages로 배포합니다.

기초를 직접 손으로 써보는 것이 목표라서 도구의 도움을 일부러 뺐습니다. 에디터는 VS Code를 권장하고, Live Server와 Prettier 확장을 설치하면 편합니다.

## 4주 동안 만드는 것

4주 내내 넷플릭스 형태의 OTT 웹사이트 **WINK PLAY**를 이어서 만듭니다. 매주 새 프로젝트를 만들지 않고, 지난주에 작성한 코드 위에 이번 주에 배운 내용을 더합니다.

```
1주차:  HTML로 화면의 구조 만들기
2주차:  CSS로 OTT 스타일과 반응형 레이아웃 만들기
3주차:  JavaScript로 검색·필터·모달·찜 기능 만들기
4주차:  작품 데이터를 분리하고 상태를 저장한 뒤 배포하기
```

| | 1주차 | 2주차 | 3주차 | 4주차 |
| --- | --- | --- | --- | --- |
| 결과물 | HTML 뼈대 | 반응형 페이지 | 움직이는 페이지 | **배포된 내 사이트** |
| 열어보는 방법 | 파일 더블클릭 | 파일 더블클릭 | 파일 더블클릭 | **URL로 접속** |
| 새로고침하면 | 해당 없음 | 해당 없음 | 다 사라짐 | **남아있음 (localStorage)** |

4주 후에는 누구나 접속할 수 있는 본인의 OTT 웹사이트와, 웹페이지가 만들어지고 동작하는 과정을 스스로 설명할 수 있는 경험을 갖게 됩니다.

## 레포 구조

주차별 폴더를 만들지 않고, **사람마다 브랜치 하나**를 씁니다. `main`에는 이 안내문만 있고, 과제는 본인 이름 브랜치에 쌓입니다.

```
main                       ← 챌린지 안내(README)만 있습니다. 과제를 올리지 않습니다
{본인이름}                  ← 내 WINK PLAY가 4주 동안 쌓이는 브랜치 (1주차에 한 번 만듭니다)
feature/{n}주차-{본인이름}   ← 그 주의 작업 브랜치. PR을 올리고 {본인이름} 브랜치에 머지합니다
```

본인 이름 브랜치에서는 레포 루트에 바로 프로젝트 파일을 둡니다. 1주차를 마친 브랜치는 아래와 같은 모습이 됩니다. 2주차부터 추가되는 파일은 주차별 자료를 따라주세요.

```
{본인이름} 브랜치
├── index.html
├── README.md      ← 이 안내문 대신 WINK PLAY 소개로 바꿔 씁니다
└── images/
```

## 과제 제출 방법

매주 과제는 두 가지로 구성됩니다.

- **필수 과제**: WINK PLAY에 해당 주차의 내용을 구현하는 누적 과제
- **키워드 과제**: 해당 주차의 핵심 개념을 본인 말로 3~5줄씩 정리하는 과제

```bash
git clone https://github.com/KMU-WINK/2026-WebBasic-Challenge.git
cd 2026-WebBasic-Challenge

# 1주차에 한 번만: 내 이름 브랜치를 만들고 올려둡니다
git checkout -b {본인이름}
git push origin {본인이름}

# 매주: 내 이름 브랜치에서 그 주의 작업 브랜치를 만듭니다
git checkout -b feature/1주차-{본인이름}
# 레포 루트에서 index.html, README.md, images/ 작업

git add .
git commit -m "feat: 1주차 WINK PLAY HTML 뼈대"
git push origin feature/1주차-{본인이름}
```

이후 GitHub에서 PR을 생성하고, 아래 [PR 템플릿](#pr-템플릿)을 채워 제출합니다. 1주차 세미나에서 clone부터 PR까지 함께 진행합니다.

**PR의 base 브랜치는 `main`이 아니라 본인 이름 브랜치입니다.** GitHub가 기본으로 `main`을 골라두니, PR을 만들 때 base를 `{본인이름}`으로 바꿔주세요. 리뷰가 끝나면 본인 이름 브랜치에 머지합니다.

```
base: {본인이름}  ←  compare: feature/1주차-{본인이름}
```

**PR을 올린다고 끝이 아닙니다.** 아래 두 가지까지 마쳐야 해당 주차 과제가 완료됩니다.

- 리뷰어가 남긴 질문에 답변하기
- 다른 참가자의 PR에 코멘트 1개 이상 남기기 (응원, 궁금한 점 모두 좋습니다)

주차가 바뀌면 머지된 본인 이름 브랜치를 받아서 새 작업 브랜치를 만들고, **지난주 코드 위에 그대로 이어서 작업**해주세요. 복사할 필요가 없습니다.

```bash
git checkout {본인이름}
git pull origin {본인이름}

git checkout -b feature/2주차-{본인이름}
```

## 브랜치 · 커밋 컨벤션

**브랜치**

```
main                      ← 안내문만. 건드리지 않습니다
 └── {이름}               ← 1주차에 main에서 한 번 만듭니다
      ├── feature/1주차-{이름}
      ├── feature/2주차-{이름}
      ├── feature/3주차-{이름}
      └── feature/4주차-{이름}
```

- 이름 브랜치는 한글 이름 그대로 씁니다. 예: `홍길동`, `feature/1주차-홍길동`
- 작업 브랜치의 PR은 `main`이 아니라 `{이름}` 브랜치로 보냅니다.

**커밋 프리픽스**

| 프리픽스 | 의미 |
| --- | --- |
| `feat:` | 새 기능 추가 |
| `fix:` | 버그 수정 |
| `refactor:` | 동작 변경 없는 구조 개선 |
| `chore:` | 설정 등 기타 |
| `docs:` | 문서, README |

## PR 템플릿

PR 본문에 아래 내용을 채워 제출해주세요.

- **「🔍 핵심 코드 설명」 칸은 필수입니다.** 비어 있으면 리뷰 없이 반려됩니다.
- **「🙋 질문」 칸을 비워두지 마세요.** 여기 적힌 질문을 모아 다음 세미나의 과제 리뷰를 구성합니다.

## 랜덤 발표

매주 세미나 시간에 참여자 중 **랜덤으로 1명**을 뽑아 대면 발표를 진행합니다. 그 주에 구현한 WINK PLAY 결과물을 직접 보여주면서 아래 내용을 간단히 공유합니다.

- 어떻게 구현했는지
- 구현하면서 어려웠던 점
- 새롭게 알게 된 내용

누가 발표할지는 미리 정하지 않습니다. **모든 참여자가 본인 코드를 설명할 수 있게 준비해주세요.**

## 질문과 추가 강의

이해하기 어렵거나 추가 설명이 필요한 내용은 편하게 질문해주세요. 특정 주제에 추가 강의가 필요하다는 의견이 나오면 투표를 진행하고, 수요가 있으면 담당 멘토가 따로 설명하는 시간을 마련합니다.

## AI 사용 가이드

ChatGPT, Claude, Copilot 등 AI 사용은 자유입니다. 단, **제출한 코드는 전부 "설명할 수 있는 내 코드"여야 합니다.** 그래서 아래 세 가지를 함께 운영합니다.

- PR의 「🔍 핵심 코드 설명」 칸 작성 (핵심 3곳을 내 언어로)
- 리뷰어 질문에 답변
- 세미나 랜덤 발표

같은 AI를 써도 질문에 따라 남는 게 달라집니다. **정답 대신 이유를 물어보세요.**

| 👎 남는 게 없는 질문 | 👍 학습이 되는 질문 |
| --- | --- |
| "OTT 메인 페이지 HTML 짜줘" | "내가 짜는데, 사진 옆에 글이 안 붙고 아래로 내려가. 왜 그래?" |
| "폼 예제 줘" | "label의 for와 id를 연결하는 게 왜 필요해? 안 하면 뭐가 달라져?" |
| "이 오류 고쳐줘" (코드 전체 붙여넣기) | "이 오류 메시지가 무슨 뜻이야? 어디부터 의심해야 해?" |

AI가 준 코드를 그대로 붙이기 전에, 모르는 태그나 문법이 있으면 그게 무엇인지 되물어보세요. 키워드 과제도 AI 답변을 그대로 옮기지 말고 본인 말로 적어주세요.
